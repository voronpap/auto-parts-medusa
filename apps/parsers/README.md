# Сервіс парсерів

Шукає номер деталі в каталогах виробників і передає каталогу магазину те, що
ці каталоги кажуть: аналоги, застосовність і характеристики.

Сервіс працює за запитом. Він забирає завдання з каталогу, проганяє номер по
джерелах і надсилає результат. Каталог до сервісу не звертається. Формат
обміну описано в [`docs/LOOKUP_FORMAT.md`](../../docs/LOOKUP_FORMAT.md).
Правила безпечного перенесення bulk-каталогу зі spool до production описані в
[`docs/PARTS-CATALOG-MIGRATION.md`](../../docs/PARTS-CATALOG-MIGRATION.md).

## Два види пошуку

**Свій бренд.** Джерело знає номер як власний товар (Bosch шукає номер Bosch)
і віддає все, що про нього має: кроси, застосовність, характеристики.

**Чужий номер.** Для номера іншого виробника — насамперед OE-номера автовиробника —
сервіс питає кожне джерело, яке вміє шукати за номерами для порівняння
(`cross_search`), які з його власних товарів йому відповідають. Так з OE-номера
виходять аналоги одразу в кількох брендах. Товар зараховується, лише коли
джерело саме вказує цей номер під цим виробником; схожий номер або той самий
номер під іншим виробником збігом не є. Зв'язок передається з
`direction: "incoming"`: посилання на запитаний номер несе товар джерела.

## GMB: відкритий каталог і збір номерів за автомобілем

Адаптер `gmb` читає видимий SKU товару та власний анонімний WordPress API
`opticat_ajax_lookup`. Режими `php=0` (JSON) і `php=1` (HTML) явно присутні
в коді сторінки: це варіанти представлення, не обхід входу. `BFBQ` — публічний
ідентифікатор виробника з тієї ж сторінки, не ключ провайдера. Транспортний
`part_number` використовується дослівно; додатковий дефіс у ньому не стає SKU
або аналогом. Власний номер і виробник перевіряються в PIES/ACES.

OE-бренд береться з `partInterchanges.brandName`, не з марки застосовності.
Коди interchange/quality не розшифровуються навмання: номери конкурентів
залишаються `COMPETITOR_REFERENCE` з `ambiguous=True`, не точними аналогами
або замінами. GTIN зі збереженими нулями — окремий `GTIN_IDENTIFIER`.
Габарити пакування явно позначено як Package, не як розміри деталі;
довгі дослівні тексти зберігаються впорядкованими фрагментами без обрізання.
Назва комплекту не створює `CONTAINS`, якщо джерело не надало номерних компонентів.

ACES-рядки зберігаються за окремими роками, без заповнення прогалин діапазоном.
Make/Model зіставляються з підписаною HTML-таблицею, а за потреби — з native
vehicle ID; багатослівні назви не діляться за першим пробілом. Умови/нотатки
не втрачаються. Зміна структури чи суперечність ідентичності/років — помилка,
не вигадані дані. `skip_fitment` підтримується, OE й характеристики залишаються.
Пауза для gmb.net завжди щонайменше 5 секунд, навіть за меншої загальної паузи.

    .venv/bin/python tools/gmb_vehicle_numbers.py --year 2016 --makes Audi --models S6 --cache /tmp/gmb.sqlite --record-output /tmp/gmb-audi-s6-responses.json

Інструмент використовує опубліковані year/make/model/engine ID і звичайний
анонімний фільтр каталогу; підтверджує напис Showing Results For та обходить
усі сторінки. `--max-models` / `--max-products` — явні пробні обмеження,
не повне наповнення. `--record-output` обов'язковий і має бути новим файлом;
кеш задається явно поза захищеною `.cache`. Сторінки з сесійним фільтром
не беруться з локального кешу, всі сирі відповіді зберігаються у sidecar,
навіть у разі помилки. Інструмент лише друкує номери, не імпортує їх у магазин.
Перевірений Audi S6 2016: `580-2620`, `180-2620`, `780-0008`.
Відсутність китайських марок у списку одного року не доводить їх відсутності
в усьому каталозі; підтвердженого покриття китайських авто цим джерелом ще немає.

## Budweg: неактивний прототип до перевірки native пагінації

`parsers/adapters/budweg.py` реалізує публічний HTML lookup і всі сторінки
окремих вкладок; `tools/budweg_make_numbers.py` — GET-пошук за опублікованою
маркою автомобіля. Адаптер **не зареєстровано в ADAPTERS**: 2026-10-14
native сторінка 2 для 343640 повернула HTTP 500; для 233411 вкладка
Compatible calipers — HTTP 500 з заголовком Database Error без товарних
вузлів; для 203427 вкладка застосовності — ReadTimeout 30 с. Частковий
результат не передається, source-відмова не обходиться й не повторюється.
Перед увімкненням треба перевірити ці посилання та повні живі lookup;
не запускати імпорт чи масовий збір за наявних збоїв.

55 офлайн-тестів (45 адаптер / 10 збір номерів) перевіряють структуру,
пагінацію, помилки й схему. Три збережені fixtures — **реальні перші
сторінки**, не повні каталоги; тестові end markers і MG-рядки синтетичні
й не є доказом живого покриття китайських авто. Всього проходять 491 тест.

OE-таблиця Budweg не підписує виробника. Після читання **всіх** сторінок
застосовності номери віддаються під кожною джерельною маркою лише як
`ambiguous=True`; це кандидатний namespace, не підтверджений Fiat/MG/OE.
Якщо марки немає, дослівний OE залишається атрибутом без вигаданого бренду.
`cross_search=False`, бо foreign matching вимагає явного підпису виробника.
EAN — окремий GTIN зі збереженими нулями. Partlist і Compatible calipers
зберігаються дослівно як сервісні посилання: не аналоги, не автоматичний
`CONTAINS` цілого ремкомплекту; placeholder article=0 не стає номером.

Власний номер перевіряється за Budweg No, не виводиться з URL.
Sparepart-застосовність читається з явно названих native filter полів;
caliper-vehicle ID звіряється за точним джерельним описом із такими
посиланнями сервісної деталі, без додавання її інших застосовностей.
Неоднозначний/відсутній binding — помилка, не вгадування моделі з пробілів.
Місяці, model_code й дужкові позначення збережено в умовах, не оголошено
кодами двигуна/поколінням. `skip_fitment` прибирає структуровані автомобілі,
але для OE все одно потрібні всі сторінки марок; це не швидкий шлях до
непідписаних кросів. Pausing для хоста завжди не менше 5 секунд,
усі запити й сирі успішні відповіді — через PoliteSession.

Після відновлення доступності, лише пробний збір без імпорту:

    .venv/bin/python tools/budweg_make_numbers.py --makes MG --max-pages 1 --cache /tmp/budweg.sqlite --record-output /tmp/budweg-mg-trial-responses.json

Параметри cache/record-output обов'язкові; cache поза захищеною `.cache`,
sidecar новий і зберігається навіть у разі помилки. Trial limits не
означають повний збір: `complete_collection=False`. Без пробних меж
інструмент читає всі native сторінки, перевіряє марку, номер сторінки й
збереження фільтра; не ремонтує посилання додаванням вгаданих параметрів.

## Сирі індекси — не підключені до каталогу

| Джерело | Що збережено | Обмеження |
|---|---|---|
| Cina Auto Parts, публічний PDF із URL 2016/12 | 2746 товарних і 12 групувальних рядків на 42 сторінках; дослівні Car brands / Product Number / Product Name | За рішенням власника лише сирий індекс. Немає підтвердженого виробника/типу номера; OE, кроси, застосовність і характеристики не створюються |

    .venv/bin/pip install -e ".[pdf]"
    .venv/bin/python tools/cina_auto_parts_index.py build /tmp/cina-catalog.pdf --output /tmp/cina-raw-index.json
    .venv/bin/python tools/cina_auto_parts_index.py find /tmp/cina-raw-index.json --number A11-3502031 --car-brand-label CHERY

Індекс містить SHA-256 оригіналу, номер сторінки, джерельні заголовки та дату
створення з PDF metadata (це не підтверджена дата видання). «Car brands»
залишається сирою міткою: серед значень є також аксесуари й фільтри. Коди в
описах не стають кросами; моделі/роки/позиції не розбираються. Групувальні
ID з порожнім Product Number збережено окремо й не шукаються як товари.
Частина описів обрізана вже в джерельному PDF; пропущений текст не відновлюється.
Сторінка з іншою структурою/видавцем або без товарів перериває побудову.
Новий вихідний файл обов'язковий: наявний індекс не перезаписується.
Не використовуйте `import-pdf` або `import-numbers` для цих невизначених кодів;
адаптера/SourceMeta/реєстрації в ADAPTERS для Cina немає.

Публічні PDF/XLSX можна зберігати через `tools/download_catalogue.py`:
HTTPS, PoliteSession, пауза 5 секунд, окремий JSON сирої відповіді, без
імпорту/запитів до Medusa. Параметри: URL, `--output`, `--record-output`,
`--cache`, `--source-key`, `--source-name` і `--parser-version`.
Сирий `body` має стандартний формат `data:<mime>;base64,...` і відновлює
оригінальні байти; граничний розмір файла 4 МБ відповідає наявному ліміту
архіву. Це не зміна схеми backend. Усі шляхи виходу мають бути новими,
кеш — поза захищеною `apps/parsers/.cache`. Вхід/captcha/HTTP-відмова/TLS
помилка не обходяться. Сирі файли не друкуйте в логах.

## Постачальники — другий тип адаптера

Адаптер джерела відповідає на питання «що каталог каже про цей номер».
Адаптер постачальника — «що цей постачальник продає, за скільки і скільки є».
Він лише читає прайс і передає рядки; прив'язку до каталогу, історію цін і
зняття з продажу робить магазин.

    .venv/bin/python -m parsers supplier-sync suppliers.d/постачальник.json

**Прайс файлом (XLSX або CSV)** коду не потребує — достатньо опису в
`suppliers.d/*.json` (зразок: `suppliers.d/example.json.sample`): назва, шлях
або адреса файла, рядок заголовків і відповідність колонок. Колонку можна
назвати текстом заголовка або літерою («A», «B»). Якщо весь прайс одного
бренду — `"brand_value": "febi"` замість колонки бренду.

**Постачальник з API чи кабінетом** — клас у `parsers/suppliers/`,
успадкований від `SupplierAdapter`: `supplier` (назва, валюта, термін
поставки) і `price_list()`, що віддає `OfferRow` для кожної позиції.

Правила для постачальників:

- `price_list()` віддає прайс **цілком**. Чого в ньому немає — магазин знімає
  з продажу. Не вдалося прочитати весь — кидай `SourceError`, а не віддавай
  частину: завантаження тоді не завершується і нічого не знімається.
- Ціну й залишок передавай так, як написав постачальник («1 234,50», «>10»,
  «в наявності»). Розбирає їх магазин — однаково для всіх.
- Бренд і номер — як у прайсі; нормалізує магазин.
- Ключі й паролі постачальників — лише в `apps/parsers/.env`, які власник
  вписує сам. У код, опис прайса, логи й коміти вони не потрапляють.
- Перерване завантаження продовжується в тому самому запуску: рядки
  накладаються повторно без шкоди.

## Правила, яких дотримується кожен адаптер

- Передає лише те, що сказало джерело. Не виводить кроси зі схожості номерів
  і не робить деталі взаємозамінними через спільну застосовність.
- Номери — точно як у джерелі, з пробілами, дефісами, нулями й суфіксами.
- Дослівне формулювання джерела зберігається в `raw_relation_text` і `raw_text`.
- Вердикт «підходить / не підходить» не ставить: це вирішує каталог.
- Номер, знайдений під іншим брендом, збігом не вважається.
- Якщо джерело має API, адаптер працює через нього; розбір HTML — запасний
  варіант.
- Вхід, captcha й захист від ботів не обходяться. Таке джерело повертає помилку
  `SourceBlocked` і пропускається.

## Як сервіс поводиться з джерелами

- представляється в заголовку `User-Agent` і дає адресу сайту;
- тримає паузу між запитами до одного хоста (типово 5 секунд);
- кешує відповіді на тиждень, щоб не питати те саме двічі;
- збій одного джерела не зупиняє решту й потрапляє в `errors` результату.

## Встановлення

    cd apps/parsers
    python3 -m venv .venv
    .venv/bin/pip install -e ".[dev]"
    .venv/bin/pytest

## Команди

    .venv/bin/python -m parsers adapters
    .venv/bin/python -m parsers lookup --brand Bosch --number "0 986 478 123"
    .venv/bin/python -m parsers run

`lookup` друкує результат і нічого нікуди не надсилає — так перевіряють
адаптер. `run` працює постійно: забирає завдання й надсилає результати.

## Налаштування

Змінні середовища для `run`:

| Змінна | Зміст |
|---|---|
| `CATALOG_URL` | адреса магазину, наприклад `http://127.0.0.1:9000` |
| `CATALOG_API_KEY` | секретний API-ключ Medusa |
| `PARSERS_WORKER` | назва цього екземпляра в журналі завдань |
| `PARSERS_CACHE` | шлях до файлу кешу відповідей |

Ключ береться лише зі змінної середовища. Його немає в аргументах команд,
коді, логах і репозиторії.

## Як додати джерело

1. Знайти, як каталог віддає дані. Спершу — чи його сторінка звертається до
   JSON API (видно в мережевих запитах браузера); якщо так, використовувати його.
2. Створити клас у `parsers/adapters/`, успадкований від `Adapter`:
   `source` (назва має збігатися з реєстром джерел каталогу), `brands`, `lookup`.
3. Зберегти кілька реальних відповідей джерела в `tests/fixtures/` і написати
   тести без мережі: збереження нулів і роздільників, напрямок `SUPERSEDED_BY`,
   номер під іншим брендом, часткові дані застосовності.
4. Додати клас у `ADAPTERS` у `parsers/adapters/__init__.py`.
5. Перевірити командою `lookup` на реальному номері.
6. Будь-яка зміна логіки розбору — нова `version` адаптера.

Для NiBK номери деталей за маркою автомобіля можна зібрати без імпорту:

    .venv/bin/python tools/nibk_model_numbers.py --brands GEELY HAVAL MG --cache /tmp/nibk-harvest.sqlite

`--max-models 1` обмежує пробний запуск однією моделлю на марку. Усі запити
цього інструмента також використовують `PoliteSession` із паузою 5 секунд.

Для Nissens доступний аналогічний інструмент:

    .venv/bin/python tools/nissens_make_numbers.py --brands MG CHERY BYD --cache /tmp/nissens-harvest.sqlite

`--max-pages 1` обмежує пробний запуск першою сторінкою для кожної марки.

Для ZF-групи список збирається окремо для кожного бренду деталей, щоб його
можна було передати до `import-numbers` без змішування брендів:

    .venv/bin/python tools/zf_model_numbers.py --brands MG HAVAL CHERY --part-brand TRW --cache /tmp/zf-harvest.sqlite

`--models "MG 6" --max-models 1 --max-pages 1` задає коротку перевірку.
Пошук і характеристики використовують анонімний JSON API нового каталогу;
застосовність і збирання номерів — відкритий API каталогу, на який він посилається.
Входу, ключів постачальника й перевірки справжності виробів адаптер не використовує.

Для офіційного регіонального переліку Geely (391 рядок, 360 різних номерів):

    .venv/bin/python tools/geely_ksa_model_numbers.py --models MONJARO STARRAY --cache /tmp/geely-ksa-harvest.sqlite

Один HTML містить усі вісім моделей, а JavaScript лише перемикає видиму таблицю.
Адаптер використовує інтервал 20 секунд і кеш. Роки, двигуни, кроси й ціни з
цього неповного переліку не виводяться. Нове джерело реєструється через
`SourceMeta` при надсиланні результату, без змін бекенду чи його статичного реєстру.

Для Metelli Group доступне відкрите дерево автомобілів; бренд деталей задається
окремо, бо адреси Cifam/Trusting/Fri.tech. можуть містити внутрішній код Metelli:

    .venv/bin/python tools/metelli_model_numbers.py --brands CHERY MG HAVAL --part-brand Metelli --cache /tmp/metelli-harvest.sqlite

`--models Tiggo --max-models 1 --max-versions 1 --max-products 3` обмежує
пробний запуск. Інструмент звіряє видимий номер на сторінці кожного товару й
друкує тільки власні номери вибраного бренду. Пауза 5 секунд; імпорту немає.
Пошук чужого номера перевіряє до шести товарів; застосовність читається окремою
публічною HTML-відповіддю «All Vehicles». Умови сусіднього рядка (дата, вісь,
гальмівна система тощо) зберігаються дослівно в `constraints` і `raw_text`.
Якщо OE не має підписаної марки й застосовність містить кілька марок, зв'язки
позначаються `ambiguous=True`. У пошуку чужого номера непідписаний OE не
зараховується навіть за однієї марки застосовності.

Для CTR публічний пошук за маркою збирає лише номери з підтвердженою
застосовністю; збіг тексту пошуку без рядка потрібної марки не зараховується:

    .venv/bin/python tools/ctr_make_numbers.py --brands HAVAL MG CHERY GEELY --cache /tmp/ctr-harvest.sqlite

`--max-pages 1 --max-products 2` — пробний запуск; без цих параметрів інструмент
читає всі сторінки. Захисна відповідь `cnt < 0` зупиняє роботу: endpoint
`security` не викликається. У lookup пошук обмежено 25 сторінками, чужий номер —
шістьма товарами. Прямі запити й архівування використовують `PoliteSession`.
Верхнє технічне поле API `oeNo` не є OE-таблицею та ігнорується. Зв'язок із
маркою береться з `applicationList` лише за збігу її OE з `oeList`; без такого
підпису кілька марок дають `ambiguous=True`. Пари, комплекти й неперевірені
списки замін не перетворюються на аналоги; їх наявність позначається в атрибутах.
Для локального виведення корейських позначок у Windows можна запускати Python
з `-X utf8`; код і налаштування сервісу для цього не змінюються.

Для FACET дерево автомобілів доступне без входу; інструмент друкує власні
номери лише після перевірки JSON-ідентичності товару й марки застосовності:

    .venv/bin/python tools/facet_model_numbers.py --brands MG --models 550 --max-models 1 --max-engines 1 --max-products 3 --cache /tmp/facet-harvest.sqlite

Без пробних обмежень читаються всі сторінки дерева легкових автомобілів.
Пошук свого номера використовує публічний JSON `Home/DettaglioFinale`;
OE/конкуренти й застосовність — HTML callback-відповіді самого каталогу.
Lookup обмежено десятьма сторінками кожної таблиці та шістьма товарами в
чужому пошуку; досягнення межі явно позначається в атрибутах. Пауза 5 секунд.
Стан callback передається як дані: JavaScript і запаковані .NET-об'єкти не
виконуються й не десеріалізуються. Коди `Stato`, `Confezione`, `SuperKit`
не перетворюються на вигадані статуси/кількості. «Replaced by» у таблиці
сторонніх номерів залишається дослівним контекстом, не заміною номера FACET.
Функція деталі зберігається в умовах, дати з місяцями — у `raw_text`;
двигун, ринок і вісь не вгадуються. PDF-by-email, captcha, облікові,
маркетингові та history endpoint-и не використовуються.

EPS використовує такий самий протокол, але запити виконуються лише до його
власного `catalogo.eps-autoparts.com`, із перевіркою назви каталогу та `Cod`:

    .venv/bin/python tools/eps_model_numbers.py --brands MG --models 550 --max-models 1 --max-engines 1 --max-products 3 --cache /tmp/eps-harvest.sqlite

Коди не перетворюються за формулою; поле `Foto` може містити код FACET і не
визначає власного номера EPS. Спільний читач FACET оновлено до 1.1.0.
У SourceMeta EPS передано спільне першоджерело `FACET`: каталоги брендів
одного виробника не є незалежними підтвердженнями. Якщо джерело EPS уже
створено в каталозі зі старим lineage, SourceMeta не перезапише наявне поле;
це має окремо узгодити власник каталогу. Бекенд і статичний реєстр не змінено.

KW (Facet) читається лише з `catalogo.kw-automotive.com`, із перевіркою
«KW Catalog» та власного `Cod`; відмінності від EPS/FACET підтверджено
на реальних відповідях. Це не каталог підвіски KW Suspensions.

    .venv/bin/python tools/kw_facet_model_numbers.py --brands MG --models 550 --max-models 1 --max-engines 1 --max-products 3 --cache /tmp/kw-facet-harvest.sqlite

Ті самі правила й межі, що FACET/EPS. Власні номери на зразок `457 001`
передаються з пробілами. Спільне першоджерело — `FACET`, а не три незалежні
підтвердження; наявне поле lineage джерела KW (Facet), як і EPS, має за
потреби окремо узгодити власник каталогу. Статичний JSON реєстру не змінено.

Прямий JSON цього сімейства може вимагати точне написання власного коду.
Якщо він не знайшов номер, читач перевіряє звичайні картки пошуку власних
номерів. Зараховується тільки точний збіг порівняльного ключа, після якого
JSON ще раз підтверджує надрукований код. Наприклад, KW `470127` → `470 127`
перевірено наживо; схожий префікс, суфікс або номер сестринського бренду не
зараховується. Версії спільного читача: FACET 1.2.0, EPS/KW 1.1.0.

Офіційний регіональний перелік MG Egypt містить 150 карток: 143 рядки
запчастин (28 різних номерів) і сім сувенірів без номерів деталей. Гальма,
електрика й фільтри для MG 5, MG 6, RX5, ZS, HS; явні модельні роки
2019–2022. Категорії охолодження в цьому переліку не знайдено.

    .venv/bin/python tools/mg_egypt_model_numbers.py --models "MG HS" "MG ZS" --categories Brakes Electrical --cache /tmp/mg-egypt-harvest.sqlite

Початковий HTML — лише частина списку. Адаптер читає публічний лічильник і
останню накопичувальну `filter`-сторінку власного `get_products_ajax`;
кількість усіх унікальних product ID має збігтися з лічильником. Неповна
відповідь/дублікати — SourceError, не хибний «повний» результат. Пауза
5 секунд, кеш і сирий архів через PoliteSession. Дозволений robots endpoint —
`/wp-admin/admin-ajax.php`; cart/login/contact/account не використовуються.
Коди на зразок `MG10767908` і `MGLPW100180` передаються дослівно: відповідність
номерам без MG джерело не стверджує. Ціни й сувеніри пропускаються; опис
«Font Brake Pad» збережено як у джерелі, без вигаданої осі/позиції. Кожен
зазначений рік — окрема застосовність, без непідтвердженого продовження
діапазону, двигуна або ринку. Джерело додається через SourceMeta; статичний
реєстр/бекенд не змінено. Для номера MG тут доречний `--number-type oem`.
