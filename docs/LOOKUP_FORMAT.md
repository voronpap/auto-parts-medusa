# Обмін із сервісом парсерів

Каталог не звертається до парсерів. Сервіс парсерів сам забирає завдання й сам
надсилає результати, тому може працювати на будь-якій машині з доступом до
сайту.

Машиночитна схема тіла результату: [`lookup-result.schema.json`](lookup-result.schema.json).
Вона генерується з коду командою
`pnpm exec medusa exec ./src/scripts/export-lookup-schema.ts` в `apps/backend`.

## Авторизація

Секретний API-ключ Medusa (Адмінка → Налаштування → Секретні API ключі).
Передається як HTTP Basic, де ключ — ім'я користувача, а пароль порожній:

    Authorization: Basic base64("<ключ>:")

Ключ зберігається в змінній середовища сервісу парсерів. У код, логи й
репозиторій він не потрапляє.

## Коли з'являється завдання

- автоматично при створенні номера в каталозі;
- вручну кнопкою «Знайти аналоги й застосовність» на сторінці номера.

На один номер існує не більше одного відкритого завдання.

## 1. Забрати завдання

    POST /admin/parts-catalog/lookup-tasks/claim
    {"worker": "parsers-1", "limit": 5}

`limit` — від 1 до 20. Відповідь:

    {"tasks": [{"id": "plook_...", "brand": "Bosch", "number": "0 986 478 123",
      "number_type": "aftermarket", "normalized_number": "0986478123"}]}

Забране завдання іншим не видається. Якщо результат не надійшов за 30 хвилин,
завдання знову стає доступним.

## 2. Надіслати результат

    POST /admin/parts-catalog/lookup-tasks/{id}/result

Тіло — до 2 МБ. Поля верхнього рівня: `worker`, `sources`, `relationships`,
`applications`, `attributes`, `errors`. Повний приклад — у промпті сервісу
парсерів і в JSON Schema.

Обмеження на один результат: 50 джерел, 500 зв'язків, 1000 застосовностей,
300 характеристик, 50 помилок.

Відповідь містить зведення:

    {"task_id": "plook_...", "summary": {"relationships_added": 4,
      "relationships_confirmed": 1, "relationships_unchanged": 0,
      "applications_added": 2, "attributes_added": 1, "skipped": 1, "errors": 0}}

На одне завдання приймається один результат; повторний відхиляється.

## Що каталог робить із результатом

**Джерела** зіставляються за назвою. Нове джерело створюється з переданими
типом, ліцензійним класом і першоджерелом (`lineage`); наявне зберігає свої.

**Номери й бренди**, на які посилаються зв'язки, створюються, якщо їх ще немає.
Бренд шукається за назвою та аліасами. Для знайдених номерів нові завдання
автоматично не ставляться, щоб пошук не розростався лавиною.

**Зв'язки.** Кожен запис стає доказом. Якщо такий зв'язок уже є, доказ
додається до нього; повтор від того самого джерела ігнорується.

**Вердикт ставить каталог, а не парсер:**

| Умова | Вердикт |
|---|---|
| Доказ із каталогу виробника авто, виробника запчастин або ліцензованої бази | «Підтверджено» |
| Те саме, але джерело вказало умови | «Умовно» |
| Збіг двох незалежних першоджерел серед магазинів і прайсів | «Підтверджено» або «Умовно» |
| Один магазин чи прайс, або кілька з одним першоджерелом | «Кандидат» |
| Запис позначено `ambiguous` | «Кандидат» |
| Тип зв'язку з групи кандидатів | «Кандидат» |
| `NOT_APPLICABLE_TO` | «Відхилено» |

Автоматично змінюються лише вердикти «Кандидат» і «Не з'ясовано». Вердикт,
який поставила людина, нові дані не перезаписують.

**Застосовність** зберігається так, як її описало джерело: марка, модель, роки,
двигун, умови. З каталогів — «Підтверджено» (або «Умовно» за наявності умов),
з магазинів і прайсів — «Кандидат».

**Помилки.** Якщо джерела відповіли помилками й нічого не знайдено, завдання
отримує стан «Помилка джерел», і пошук можна запустити знову. Якщо просто
нічого не знайдено — «Виконано».

**Пропущене.** Запис пропускається й рахується в `skipped`, якщо він посилається
на джерело, якого немає в `sources`, не має цільового номера, вказує на той
самий номер або дублює вже збережене.
